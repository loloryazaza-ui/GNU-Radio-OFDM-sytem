ENG:
	When running the simulation model on the radio channel, certain difficulties arose. Their solutions are provided in this section.
The main error during system startup is a buffer that is too small. The following error is returned: <block header_payload_demux(31)>]: Buffer too small for min_noutput_items. This error indicates that the Header/Payload Demux block cannot process the input elements because its minimum buffer is too small. This problem can be solved by increasing the block's minimum buffer 

	However, this solution results in the following error: block_executor :error: sched: <block header_payload_demux(28)> is requesting more input data than we can provide. ninput_items_required = 48720 max_possible_items_available = 8191. If this is a filter, consider reducing the number of taps. This error indicates that the Header/Payload Demux block requires 48,720 elements, while the previous block can only output 8,191. The initial number of elements (8,191) is set by the GNU Radio system settings and is stored in the .config\gnuradio\config.conf file. However, changing this file will have no effect. To resolve this error, increase all minimum buffers in all transmitter blocks. After this, the system will function correctly.

	The second main issue is with the HackRF One with the Portapack H2 Kit-4. This device performs better as a receiver, but when operating at 2.4 MHz, the system freezes for an indefinite period, depending on the amount of data transferred through the USB controller. This error is most likely caused by the fact that this SDR platform comes with a USB micro 2.0 controller, which is rated for a maximum speed of 480 Mbps. It is recommended to avoid using this device in further research and development.

RUS:
	При запуске имитационной модели на радиоканале, возникли определенные трудности. Их решение приведено в данном пункте.
Основная ошибка при запуске системы – слишком маленький буфер. При запуске системы выдается ошибка: <block header_payload_demux(31)>]: Buffer too small for min_noutput_items. Данная ошибка сигнализирует о том, что блок Header/Payload Demux не может обработать входящие в него элементы, поскольку его минимальный буфер слишком маленький. Данная проблема решается увеличением минимального буфера блока 
 
	Однако такое решение приводит к следующей ошибке: block_executor :error: sched: <block header_payload_demux (28)> is requesting more input data than we can provide. ninput_items_required = 48720 max_possible_items_available = 8191 If this is a filter, consider reducing the number of taps. Данная ошибка говорит о том, что блок Header/Payload Demux требует 48720 элементов, а предыдущий блок, может выдать только 8191. Изначально количество элементов в 8191 задано системными настройками в GNU Radio и хранятся в файле .config\gnuradio\config.conf, однако изменение данного файла не принесет результатов. Для решения этой ошибки необходимо увеличить все минимальные буферы во всех блоках передатчика. После этого, система будет работать корректно.

	Вторая основная проблема – HackRF One с Portapack H2 Kit-4. Данное устройство лучше работает в качестве приемника, однако при работе на частоте 2,4 МГц., у системы происходит зависание на неопределенное время, зависящее от объема пропускаемых через USB контроллер данных. Наибольшая вероятность, происхождения данной ошибки обусловлено тем, что данная SDR-платформа поставляется с контроллером USB micro 2.0., который рассчитан на максимальную скорость до 480 Мбит/с. В дальнейших исследованиях и работах рекомендуется отказаться от использования данного устройства.
